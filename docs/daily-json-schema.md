# Daily JSON Schema — Conceptual Contract

```json
{
  "schemaVersion": "1.0",
  "planType": "daily-study-plan",
  "date": "YYYY-MM-DD",
  "dayNumber": 1,
  "weekNumber": 1,
  "status": "not_started | in_progress | completed",
  "schedule": [
    {
      "blockId": "mathematics",
      "start": "11:00",
      "end": "1:00",
      "label": "Mathematics",
      "focus": "New Lectures + Questions",
      "category": "study",
      "subjectId": "mathematics-i",
      "taskIds": [
        "mathematics-i:1:L1.1"
      ]
    }
  ],
  "tasks": [
    {
      "taskId": "mathematics-i:1:L1.1",
      "subjectId": "mathematics-i",
      "courseId": "BSMA1001",
      "weekNumber": 1,
      "sourceId": "L1.1",
      "type": "lecture",
      "title": "Display title",
      "planned": true,
      "durationSeconds": 1249,
      "questionCount": null,
      "planning": {
        "unitId": "mathematics-i:1:L1.1",
        "videoMinutes": 20.8,
        "noteMinutes": 13.9,
        "questionMinutes": null,
        "estimatedMinutes": 34.8,
        "sourceDurationMissing": false,
        "sourceQuestionsMissing": false
      }
    }
  ],
  "completion": {
    "totalTasks": 0,
    "completedTasks": 0,
    "percent": 0
  },
  "meta": {
    "createdAt": null,
    "updatedAt": null,
    "notes": "",
    "generator": "planner-engine"
  }
}
```

The schedule and task list are generated by the planner engine (Phase 3). See `docs/planning-rules.md` for the exact rules and `src/js/planner-engine.js` for the configuration.

Phase 2 reconciliation: `taskId` is `<subjectId>:<weekNumber>:<sourceId>` (date-independent) and the syllabus reference field is `sourceId` (previously shown as `syllabusItemId`).

Phase 3 update: canonical plan files omit `completed` / `completedAt` (plan is not state — completion lives in `storage.js`); the validator still accepts those fields optionally for export workflows. Every schedule block references its tasks through `taskIds`, and every task must be referenced by exactly one block.
